# 웹앱 보고 (Phase 2~4 통합)

주소: https://leftdrawer.github.io/galaxy3d-viewer/

## 데모

갤럭시 3D 원본(HEIC·MP4)이나 SBS jpg/mp4를 끌어다 놓는다. 폰은 가로로 눕히고 전체화면, 처음 한 번 크기 보정(신용카드).

로컬 확인: `python -m http.server 8765` (저장소 루트) → http://127.0.0.1:8765/web/ . `web/g3d.mjs·g3d.wasm`은 Actions 산출물(github-pages 아티팩트)에서 받아 넣는다.

## 보고

계획서의 Phase 2(뷰어)·3(브라우저 사진 변환)·4(브라우저 영상 변환)를 한 페이지로 묶었다(아키텍처는 크로스체크 후 결정: 변환 후 재생). 영상은 FFmpeg 8.1 최소 빌드(mov+hevc, wasm simd128, 1.5MB)가 워커에서 두 시점을 풀고, 프레임마다 Stereo 3D 사이드데이터의 view로 좌우를 정해 SBS I420로 합친다. 이를 WebCodecs H.264(하드웨어)로 인코딩하고 원본 AAC를 그대로 붙여 mp4로 만든다(mediabunny). 사진은 libheif-js로 'ster' 그룹의 item id를 찾아 두 장을 푼다. 둘 다 앞·중간·끝(사진은 1장) 시차를 블록 매칭으로 재서 메타데이터를 검산하고, 어긋나면 시차를 따른다. 파일은 워커 메모리와 blob URL에서만 처리되고 네트워크로 나가지 않는다. 서비스 워커가 앱 파일 12개를 캐시해 두 번째 방문부터는 오프라인에서도 열린다.

## 실측 (2026-10-08, PC 크롬 계열 브라우저, 단일 스레드 wasm)

| 입력 | 결과 |
| --- | --- |
| 3D 사진 20261006_035542.heic | 1.2초, 시차 dx +28 (Python 28.8과 일치) |
| 3D 영상 7.3초(219프레임) | 16.3초, 초당 13.5프레임, 3840×1080 H.264(avc1.640033), 길이 7.297초·소리 정상·끊김 0 |
| 3D 영상 19.5초(584프레임) | 57.4초, 초당 10.2프레임 |
| SBS mp4(PC 변환기 결과) | 0.3초에 재생 |
| 평면 JPEG(.heic 확장자) 3장 | 거부 + 재전송 안내 |

```
node web/stereo.test.mjs  → stereo ok { dx: 12, n: 792 } { dx: -12, n: 792 }
node web/heic.test.mjs    → 20261006_035542.heic ster [ 154, 105 ] decode 906 ms dx { dx: 28, n: 848 }
```

## 알려진 한계

- 영상 디코딩은 단일 스레드라 PC에서도 실제 길이의 2~3배 걸린다.
- 10bit·HDR 영상, 회전 메타데이터 영상은 샘플이 없어 미검증(10bit는 오류로 안내).
- 사진 SBS 저장 버튼은 없다(영상만 저장 가능). 필요하면 추가.
- 확인용 보조 모드(애너글리프·위글)는 넣지 않았다.
